\chapter{Conclusion}\label{ch:conclusion}

This thesis presented an application layer monitoring tool for the Shibboleth IdP that detects 
documented vulnerabilities, configuration weaknesses and anomalous authentication behaviour by 
combining three separate sources of information from within the IdP. 
These sources are the audit log, two interceptors in the authentication flow and the configuration 
and metadata of the SPs. 
The collected data is transmitted to an external backend, where it is stored, correlated and 
evaluated against a catalogue of fifteen detection rules. 

For the first research question, the IdP aggregates security relevant data through the three 
channels. 
What each source can see is defined by their positions in the processing sequence, which is why their 
combination allows comparisons that no single source supports on its own. 
The configuration describes what is intended for an SP, while the audit log and the interceptors 
record independently of each other what actually happened. 
For the second question, the records of a login can be linked reliably as long as the audit log records the 
identifier of the request or the pseudonymised user and address. 
Only a correlation by time alone fails when login at the same SP follow each other within less than 100\,ms. 
The rules correlate observed logins to the declared configuration and to each other, and all of them behaved 
as specified in the tested scenarios. 
For the third question, asynchronous transmission introduced no measurable latency overhead. 
The cost appears as processor time instead. 

This thesis also identified limitations that follow from the observation point. 
Several federation level attack scenarios occur at a different system layer, involve a different 
party or are observable only through their preconditions. 
The comparison of independent records shows that two records disagree, but not which of them was 
altered. 

What this thesis contributes is therefore not a new architecture for collecting and correlating 
security events. 
It shows that an interceptor inside the authentication flow provides a second record of each login, 
which is produced and transmitted independently of the audit log. 
Combined with the audit log and the configuration, this record allows each login to be compared with 
the declared state of its SP and with the audit entry of the same login. 
In addition, the thesis analyses which properties are observable from which position and provides 
an implementation. 
Future work could extend the observation to the SPs, transfer the approach to OpenID Connect and 
evaluate the rules on labelled productive traffic.
